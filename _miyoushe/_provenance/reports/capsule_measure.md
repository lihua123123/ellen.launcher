# 11px 胶囊宽度实测（微软雅黑，FontSize 11 = 每汉字 11px）

胶囊样式取自 `MonsterArchiveSkillTemplate` 的既有实现：`Padding="6,1"` + `CornerRadius="4"` + `FontSize="11"`，无边框。
→ **总宽 = 12 + 11n**（n = 汉字数）

| 候选文案 | 汉字数 | 胶囊总宽 (DIP) | 说明 |
|---|---|---|---|
| 单读 | 2 | **34** | single-read |
| 已复核 | 3 | **45** | cal-gold（短） |
| 双读一致 | 4 | **56** | 2geo |
| 目视复核 | 4 | **56** | cal-gold |
| 目视裁决 | 4 | **56** | eyeball |
| 双几何一致 | 5 | **67** | 2geo（长） |

参考：现有技能标签（2 字，如「输出」）也是 **34 DIP**，与本方案同量级 → 视觉上不会突兀。

## 两个候选落点的可用宽度

### 落点 1：标题行（`Monster.Title` 旁）—— 问题：**语义对不上**
布局：`StackPanel Orientation=Horizontal Spacing=12` 内含 `Title` + `HyperlinkButton`，
外层第一列 `MaxWidth=800`、`Padding=16` → 可用 **768 DIP**

| 项 | 宽度 (DIP) |
|---|---|
| 最长 Title（11 字，「超重型陆巡舰·机动战垒」）@20px | 205 |
| Spacing | 12 |
| 胶囊「双读一致」 | 56 |
| Spacing | 12 |
| `@Csxylic 米游社` 链接 | ~112 |
| **合计** | **~397 / 768 → 余 371，无碰撞** |

**⚠️ 但语义对不上**：标题行只能显示**常态行**的 evidence，而用户举的两个例子恰好常态行没有 evidence：

- `14/014` → 档案条目「养育的增殖生命体」（元数据 Title「终末绿洲的守望者」）
  - 常态行 evidence = `**（无）**`
  - 状态「辅助」evidence = `eyeball`
- `17/001` → 档案条目「嵌合翼骏狮」（元数据 Title「单体的协奏者」）
  - 常态行 evidence = `2geo`

### 落点 2：`抗性数据` 标题行（推荐）
布局：`StackPanel`（**竖向**）里 `TextBlock「抗性数据」` 独占一行，
下面的 `ComboBox` 与抗性网格是另两行 → 胶囊**不与下拉争水平空间**

| 项 | 宽度 (DIP) |
|---|---|
| 「抗性数据」@14px | 56 |
| Spacing | 12 |
| 胶囊「双读一致」 | 56 |
| **合计** | **124 / 768 → 余 644** |

**且语义正确**：跟着当前选中的状态走 —— 选中「常态」显示常态行等级，
切到「辅助」显示该状态的等级（`14/014` 的 `eyeball` 恰好在这里才看得到）。

### 落点 3：状态下拉的**选项内**（每个状态各带一个胶囊）
最长状态名 5 字（「起身(升空」）@14px = 61，加 Spacing 12 + 胶囊 56 = **129**

下拉是 `HorizontalAlignment="Left"` **按内容自适应宽度** → 不会溢出，只是下拉框会变宽。
好处：**一屏看全所有状态的等级**；代价：需改 `ComboBox.ItemTemplate`（现在是 `DisplayMemberPath="Name"`），
且 33 条只有 1 个状态的条目也会显示，略显冗余。
